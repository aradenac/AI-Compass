# Role-separated Workgroup profiles and Engineer home prototypes

Two independent HTML pages: `workgroup-profiles.html` and `my-ai-workspace.html`. The index is a standalone documentation-only entry, **not** a role switcher in the product. No direct switch between experiences in either page.

Workgroup Studio hosts shared, collaborative modules; **no personal Workgroup workspace**. The Workgroup Profiles view configures user IDE, OS, WSL eligibility, specialties and task assignments (including bulk edits and phase/specialty task grouping).

My AI Workspace is the signed-in engineer's primary landing, with relevant Tasks, published/qualified applicable AI Solutions, contextual guides, personal accessibility and self-confirmation of tested setup. Workgroup members only see the engineer view when they have a separately authorized User experience and choose that experience in the top-level account/session switcher.

Role switching requires current-grant enforcement on the backend; demo links are not security controls. Profile/workload personalization requires a strictly self-scoped projection without privileged labor rates, colleague assignments or other confidential data. Access confirmations must not override verified entitlement and deployment audit requirements.

Fictional standalone HTML; no Server integration, no authentication simulation, no real changes.
